Un lenguaje de programación

Escribir automatización, no solo pulsar botones. Elige un lenguaje y llévalo a la fluidez básica.

PythonGoJavaScript
0% completado

DevOps sin código es un operador eterno. Con un lenguaje puedes convertir un ritual de 40 clics en un script revisable, testeable y versionado.

Conferencia

Elige uno. Domínalo.

Python, Go y JavaScript son los más comunes en este oficio. Python brilla en scripts, APIs y pegamento. Go en CLIs, agentes y servicios concurrentes. JavaScript/TypeScript en tooling de front, GitHub Actions y lambdas. El curso no te pide los tres: te pide uno con criterio.

Python es el más recomendable para empezar: se lee casi como prosa, se interpreta al momento y hay librerías para SSH, HTTP, YAML y nubes.

Correctitud, diseño, estiloUn script de 30 líneas también se diseña. Nombres claros, funciones cortas, cero secretos en el código, y un README que explique cómo correrlo.

Conceptos que no son opcionales

  • Sintaxis, variables, tipos.
  • Condicionales y bucles.
  • Funciones y módulos.
  • Listas, diccionarios y manejo de errores.
  • Leer archivos, JSON/YAML y hacer una petición HTTP.

Automatizar lo aburrido

El primer programa útil de DevOps no es un algoritmo elegante: es el que lista instancias, rota un log, valida un manifiesto o abre un ticket. Si ahorra trabajo humano repetible, ya es ingeniería.

import json, urllib.request
url = "https://httpbin.org/get"
with urllib.request.urlopen(url) as r:
    data = json.load(r)
print(data["url"])

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

Python

Legible, enorme ecosistema, ideal para pegar APIs y archivos. Empieza aquí si no tienes preferencia.

Go

Binario único, excelente concurrencia, muy usado en Kubernetes y CLIs. Curva más estricta, pago después.

JavaScript

El lenguaje del navegador y de Node. Útil si ya vives en el ecosistema web o en GitHub Actions.

Prueba pequeña

Si no puedes explicar un if, un for y una función, aún no automatices producción.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Instala el runtime (Python 3 recomendado).
  2. Escribe un script que imprima el día y liste archivos de un directorio.
  3. Añade un argumento de línea de comandos.
  4. Maneja un error (archivo que no existe) sin trazar un pánico ilegible.

Problem set

Rúbrica: correctitud — El script hace lo que promete el README. · diseño — Funciones cortas, una responsabilidad, errores manejados. · estilo — Nombres honestos, sin secretos, formato consistente.
