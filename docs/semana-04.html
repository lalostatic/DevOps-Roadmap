Conferencia

Protocolo: un contrato de conversación

Un protocolo de red es un conjunto de reglas para transmitir datos entre dispositivos distintos. No importa que un lado sea Go y el otro Python: ambos hablan HTTP, DNS o SSH.

El modelo OSI (7 capas) es un mapa mental, no un aparato. TCP/IP es lo que realmente corre. Tú, en la práctica, vives en: IP, TCP/UDP, TLS, HTTP y DNS.

Lo que debes poder explicar

  • Qué es una IP, una máscara y un puerto.
  • La diferencia entre TCP (confiable) y UDP (rápido y olvida).
  • Cómo un nombre (example.com) se convierte en IP (DNS).
  • Qué hace SSH y por qué las llaves ganan a las contraseñas.
  • Cómo un firewall decide qué entra y qué no.
HTTP no es 'internet'HTTP es un protocolo de aplicación. Viaja sobre TCP (o QUIC). HTTPS es HTTP sobre TLS. Si mezclas estos términos en una incidente, el equipo pierde tiempo.

Seguridad como hábito

Principio de mínimo privilegio, superficies pequeñas, secretos fuera del código, y no exponer paneles a 0.0.0.0 sin autenticación. DevSecOps no empieza en la semana bonus: empieza cuando abres el primer puerto.

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

DNS

Jerarquía de nombres. El resolvers pregunta, los nameservers responden. TTL decide cuánto cacheas.

Puertos

22 SSH, 53 DNS, 80 HTTP, 443 HTTPS. Un puerto cerrado es una puerta sin timbre.

SSH

Shell remoto cifrado. Autenticación por llave. Túneles y port forwarding son superpoderes.

Firewall

Reglas: de dónde, a dónde, qué protocolo. Deny by default es más sano que allow all.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Resuelve un dominio con dig o nslookup y lee la cadena de registros.
  2. Abre una conexión HTTP con curl -v y nombra cada fase.
  3. Genera un par de llaves SSH y entra a tu VM sin contraseña.
  4. Lista puertos abiertos con ss -tulpn.
