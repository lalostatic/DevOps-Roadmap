El código no sirve si el proceso se cae, el disco se llena o el certificado caduca. Administrar servidores es el oficio de la confiabilidad cotidiana.

Conferencia

Tres objetivos

  • Minimizar lentitud y caídas; maximizar confiabilidad.
  • Construir entornos seguros.
  • Escalar servidores y operaciones cuando la organización crece.

Proxies, cachés y servidores web

Un proxy inverso (Nginx, Caddy, HAProxy, IIS ARR) recibe el tráfico del mundo y lo reparte a tus aplicaciones. Termina TLS, compacta, limita, enruta. Un proxy directo es el que usan los clientes para salir; no los confundas.

Un servidor de caché guarda respuestas caras cerca de quien las pide. Un servidor web (Nginx, Apache, IIS) habla HTTP. En la práctica, Nginx suele ser las tres cosas: web, proxy inverso y, con un poco de configuración, caché.

Caja negraEl usuario habla con un nombre y un puerto. Detrás puede haber 1 o 50 procesos. El proxy es la fachada. Si la fachada está mal, nada interior importa.

Operar

systemctl, logs, rotación, actualizaciones, backups, certificados, límites de ulimit, espacio en disco. Un servidor sin backup es un prototipo.

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

Reverse proxy

El mundo habla con Nginx; Nginx habla con tu app en 127.0.0.1:3000.

Caché

No recalcules lo que no cambió. Ojo: invalidar caché es el problema difícil.

Firewall

El servidor no necesita 65535 puertas abiertas. Abre las que el diseño pide.

Load balancing

Varios backends, una fachada. Salud, reintentos, afinidad: detalles que evitan dramas.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Instala Nginx en Ubuntu.
  2. Sirve una página estática.
  3. Pon un proxy_pass a un proceso local (python -m http.server o similar).
  4. Fuerza HTTPS local con mkcert o un certificado autofirmado de laboratorio.

Problem set

Rúbrica: correctitud — La app responde a través del proxy, no a puerto crudo público. · diseño — TLS, logs y un plan de backup existen aunque sean simples. · estilo — La configuración está en Git, no solo en el servidor.
