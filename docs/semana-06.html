Conferencia

Qué es un contenedor

Un contenedor es una unidad estándar de software que empaca código y dependencias para que la aplicación corra igual de un entorno a otro. No es una VM: comparte el kernel del anfitrión y aísla procesos, sistemas de archivos y red.

Una imagen es la receta inmutable. Un contenedor es la instancia en ejecución. El Dockerfile describe cómo se construye la imagen.

Lo que debes practicar

  • Correr contenedores, ver logs y entrar con exec.
  • Escribir Dockerfiles pequeños y reproducibles.
  • Volúmenes para persistir datos.
  • Redes: cómo dos contenedores se hablan por nombre.
  • Docker Compose para más de un contenedor.
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "app.py"]
Capa sobre capaCada instrucción del Dockerfile es una capa. El orden importa: copia lo que cambia poco primero para no invalidar la caché.

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

Imagen vs contenedor

La imagen es la clase; el contenedor es el objeto. Puedes lanzar muchos de una.

Volumen

Sin volumen, el disco del contenedor se esfuma al borrarlo. Las bases de datos necesitan memoria persistente.

Red bridge

Compose crea una red. servicio-a puede resolver servicio-b por DNS interno.

Usuario no root

Correr como root dentro del contenedor es un atajo que se paga en incidentes.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Instala Docker Engine o Docker Desktop.
  2. Corre nginx:alpine y ábrelo en un puerto local.
  3. Escribe un Dockerfile para un script de la semana 2.
  4. Crea un compose con app + un redis o postgres de laboratorio.

Problem set

Rúbrica: correctitud — docker compose up --build funciona en una máquina limpia. · diseño — Capas ordenadas, .dockerignore, un proceso por contenedor. · estilo — Nombres de servicio claros, sin latest en producción si puedes fijar tags.
