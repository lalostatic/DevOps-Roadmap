Conferencia

Dos oficios que se confunden

Aprovisionar es crear la materia: redes, VMs, buckets, clústeres. Terraform, Pulumi, CloudFormation, Bicep viven aquí. Configurar es dejar esa materia en el estado deseado: paquetes, usuarios, plantillas. Ansible, Chef, Puppet, y a veces cloud-init.

Terraform es hoy el aprovisionador más portable entre nubes. El estado (state) es sagrado: describe qué existe de verdad. Sin backend remoto y locking, dos personas se pisan.

El entorno como oroSi tardas una semana en recrear staging, no tienes IaC: tienes arqueología. El estándar es nacer un ambiente bajo demanda.

Service mesh, en una idea

Cuando hay muchos servicios, el malla (Istio, Linkerd, Consul) mueve mTLS, reintentos y observabilidad al lado de cada pod. No lo necesitas el primer día. Sí debes saber que existe y qué problema ataca.

Drift

Alguien cambió algo a mano en la consola. El próximo plan lo va a pelear.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Instala Terraform.
  2. Haz un laboratorio local (local_file o Docker provider) para entender init/plan/apply/destroy.
  3. Lee un plan antes de aplicar. Siempre.
  4. Destruye todo. El teardown es parte del oficio.

Problem set

Rúbrica: correctitud — plan es legible; apply es reproducible. · diseño — Módulos y variables; secretos fuera. · estilo — Nombres consistentes; state no se sube al git público.
