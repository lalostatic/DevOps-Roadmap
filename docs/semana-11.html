Semana 11 · 12–20 h

Un proveedor cloud

Pensar en APIs de infraestructura, no en un único servidor bajo el escritorio.

IaaS, PaaS, SaaSDisponibilidadAdministraciónDiseño e implementación
0% completado

Los proveedores exponen APIs para crear recursos con fronteras de seguridad y de cobro. La nube corre en centros de datos, pero se siente como una plataforma. Saber provisionar, configurar y asegurar es el corazón del DevOps moderno — y de su complejidad.

Conferencia

Elige uno y baja a tierra

AWS, Azure y Google Cloud dominan el mercado. Elige el que te abra más puertas en tu región o empleo objetivo. Los conceptos viajan: identidad, red, cómputo, almacenamiento, observabilidad, IAM.

IaaS: alquilas VMs y discos. PaaS: te dan la plataforma (app service, Cloud Run, Elastic Beanstalk). SaaS: usas el software. DevOps vive sobre todo entre IaaS y PaaS.

Lo que debes practicar

  • Usuarios, roles, políticas. Nunca uses la cuenta root para el día a día.
  • VPC/VNet, subnets públicas/privadas, NAT, security groups.
  • Máquinas virtuales, discos, snapshots.
  • Disponibilidad: zonas, regiones, backups, RPO/RTO en lenguaje humano.
La nube no perdona el olvidoTodo recurso tiene precio. Un laboratorio sin destroy es una factura. Etiqueta, presupuesto, alarma de costo.

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

IAM

Quién puede qué sobre cuál recurso. El error más caro es una llave de admin en un repo.

Región y zona

La región es un geografía; la zona es un edificio (casi). Multi-AZ no es multi-región.

Security group

Firewall de instancias. Egress también importa.

Cuenta y organización

Separa prod de sandbox. El blast radius es un diseño, no un accidente.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Crea una cuenta de laboratorio (free tier) y activa MFA.
  2. Crea un usuario/rol de trabajo, no uses root.
  3. Levanta una VM mínima, entra por SSH, apágala.
  4. Mira la factura. Configura una alerta de costo.

Problem set

Rúbrica: correctitud — El lab se puede crear y destruir con instrucciones claras. · diseño — IAM mínimo, red justificada, sin 0.0.0.0/0 en SSH si puedes evitarlo. · estilo — Etiquetas y alerta de costo.
