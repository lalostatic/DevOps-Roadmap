Orquestación de contenedores

Dejar de cuidar contenedores a mano. Kubernetes (o similar) declara el estado deseado y el clúster se esfuerza por cumplirlo.

Un contenedor es un proceso. Diez contenedores son un sistema. Cuando hay que reiniciar, escalar, sanar y exponer servicios, aparece el orquestador.

Conferencia

Qué orquesta un orquestador

La orquestación automatiza despliegue, gestión, escala y red de contenedores. Sirve en cualquier entorno donde ya usas contenedores: el mismo manifiesto puede acercarte a desarrollo, staging y producción.

Los microservicios en contenedores se vuelven manejables cuando el orquestador se ocupa del almacenamiento, la red y parte de la seguridad.

Kubernetes, sin mito

Un clúster tiene plano de control (API server, scheduler, etcd, controllers) y nodos de trabajo. Tú declaras: 'quiero 3 réplicas de esta imagen, con este puerto'. El control loop compara el mundo real con el declarado.

  • Pod: el átomo. Uno o más contenedores que viajan juntos.
  • Deployment: cómo se actualizan los pods.
  • Service: un nombre estable frente a pods que nacen y mueren.
  • Namespace: paredes de papel para equipos y ambientes.
kubectl get nodes
kubectl create deployment web --image=nginx
kubectl expose deployment web --port=80 --type=ClusterIP
kubectl get pods -A
No empieces en un EKS de 20 nodosKind, k3d o minikube bastan para aprender el idioma. El cloud es la semana 11.

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

Estado deseado

Tú no 'arrancas' tanto como 'declaras'. El clúster reconcilia.

kubectl

El CLI. Habla con el API server. Casi todo es un objeto YAML.

Namespace

No es un firewall mágico, pero organiza y aplica cuotas y RBAC.

Rollout

Un Deployment cambia pods poco a poco. Un crashloop es información, no un misterio.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Instala kubectl y un clúster local (kind/k3d/minikube).
  2. Despliega nginx y expónlo.
  3. Escala a 3 réplicas y observa los pods.
  4. Aplica un cambio de imagen y sigue el rollout.

Problem set

Rúbrica: correctitud — El YAML aplica en un clúster limpio. · diseño — Probes, recursos (CPU/RAM) y nombres con sentido. · estilo — Sin kubectl apply de objetos sueltos sin etiqueta ni namespace.
