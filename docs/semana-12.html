Vas a convivir con desarrollo en un mundo Scrum (o similar). Necesitas el ciclo de vida del software, las herramientas de ese ciclo, y cómo se prueba en automático para poder meterlo al pipeline.

Conferencia

El ciclo y el ritual

SDLC: idea, análisis, diseño, implementación, prueba, despliegue, operación, mejora. Ágil no elimina el ciclo: lo hace corto y visible. Scrum propone backlog, sprint, daily, review, retro. Kanban visualiza el flujo. Elige el que el equipo ya usa y mejóralo con datos, no con dogmas.

Calidad integrada (built-in quality): tests automáticos, revisiones, contratos de API, feature flags. El QA no es una casta al final; es una propiedad del tubo.

Comunicación y troubleshooting

Incidentes se narran: qué vimos, cuándo, qué hipótesis, qué se hizo, qué se aprendió. Blameless no es 'nadie es responsable': es 'el sistema permitió el error y el sistema se repara'.

Eres parte del productoUn pipeline inestable, un entorno que nadie puede recrear o un canal de Slack sin runbooks son deuda de ingeniería, no 'cosas de ops'.

Cortos

Un concepto por tarjeta. Léelos en voz alta si puedes.

Backlog

Lista ordenada de valor. Si todo es P0, nada es P0.

Definición de Terminado

En producción, observable, con rollback. No 'en mi rama'.

Pirámide de tests

Muchos unitarios, menos de integración, pocos E2E caros.

Postmortem

Timeline, causa contribuyente, acciones. Sin villanos.

Recorrido

Como el walkthrough de CS50: solo para arrancar, no para sustituir el problem set.

  1. Lee una guía corta de Scrum y anota rituales vs principios.
  2. Toma un bug ficticio y escribe un reporte reproducible.
  3. Diseña una pirámide de tests para la app de la semana 6.
  4. Escribe un postmortem de un incidente inventado pero realista (certificado vencido).

Problem set

Rúbrica: correctitud — Las historias se pueden probar. · diseño — El postmortem tiene timeline y acciones. · estilo — El lenguaje es preciso, sin jerga de adorno.
